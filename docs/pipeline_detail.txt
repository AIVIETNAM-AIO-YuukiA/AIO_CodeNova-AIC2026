MỤC ĐÍCH:
  Xây dựng hệ thống Video Question Answering (VQA) cho HCMC AI Challenge 2025.
  Gồm 4 bài toán: Textual KIS, Video KIS, VQA, TRAKE.
  Video mẫu: 1.mp4 (25926 frames, ~9 phút) → 31 keyframes.

CÔNG NGHỆ CHÍNH:
  - Python >= 3.13, uv package manager
  - CLIP (ViT-B/32) → text + image embeddings
  - FAISS (CPU) → vector search (31 vectors, <1ms)
  - Gemini 2.5 Flash Lite (cloud) / Ollama + moondream (local vision)
  - Windows + CUDA (GPU cho CLIP, CPU cho FAISS)

II. GIAI ĐOẠN 1: TEMPORAL SEARCH (src/retrieval/temporal_search.py)
───────────────────────────────────────────────────────────────────────────────

  ══════════════════════════════════════════════════════════════════
  PROBLEM:
  ══════════════════════════════════════════════════════════════════
  CLIP search trả về top-K frame có điểm cao nhất, nhưng các frame
  này có thể nằm rải rác trong video, không có ngữ cảnh thời gian.

  ══════════════════════════════════════════════════════════════════
  THUẬT TOÁN (theo tài liệu training):
  ══════════════════════════════════════════════════════════════════

  Input:
    - start_idx: vị trí frame khớp query (từ CLIP search)
    - frame_embeddings: ma trận [N x D] image embeddings (sorted)
    - tolerance_threshold: mặc định 3

  Forward search (dò tìm phía trước):
    current_kf = frame_embeddings[start_idx]
    best = -1
    tolerance = 0
    for idx in range(start_idx+1, N):
        similarity = cosine(current_kf, frame_embeddings[idx])
        if similarity >= best:
            best = similarity
            tolerance = 0
        else:
            tolerance += 1
            if tolerance == threshold:
                return idx - threshold  # end of segment

  Backward search (dò tìm phía sau - mở rộng từ slides):
    Tương tự forward nhưng đi ngược về đầu.

  ══════════════════════════════════════════════════════════════════
  GIẢI THÍCH:
  ══════════════════════════════════════════════════════════════════
  - So sánh FRAME VỚI FRAME (không phải query với frame)
  - Tìm biên giới shot: khi frame khác quá nhiều so với start frame
  - tolerance = số frame liên tiếp không cải thiện similarity
  - tolerance càng lớn → segment càng dài (exploration)
  - tolerance càng nhỏ → segment càng ngắn (exploitation)

  ══════════════════════════════════════════════════════════════════
  MULTI-SEGMENT (find_segments):
  ══════════════════════════════════════════════════════════════════
  1. Từ mỗi frame trong top-K CLIP result
  2. Chạy forward + backward search
  3. Gộp segment chồng lấn (overlap < min_gap)
  4. Trả về list segments sorted theo start_pos

  ══════════════════════════════════════════════════════════════════
  CODE:
  ══════════════════════════════════════════════════════════════════
    temporal_search_forward(start_idx, embeddings, tolerance=3) → end_pos
    temporal_search_backward(start_idx, embeddings, tolerance=3) → start_pos
    find_segments(start_indices, embeddings, tolerance=3, min_gap=2) → [segments]

III. GIAI ĐOẠN 2: SHOT GATHERING + SHOT VALIDATION
───────────────────────────────────────────────────────────────────────────────

  ══════════════════════════════════════════════════════════════════
  gather_frame_s (src/retrieval/temporal_search.py)
  ══════════════════════════════════════════════════════════════════
  Gom các frame trong segment [start_pos, end_pos] thành ShotInput
  (không cần window_size vì segment đã xác định đúng biên giới).

  ShotInput chứa:
    - frame_paths: list đường dẫn ảnh
    - frame_count: số lượng frame
    - start_timestamp, end_timestamp: thời gian trong video
    - video_id, video_name

  ══════════════════════════════════════════════════════════════════
  ShotValidator (src/retrieval/temporal_search.py)
  ══════════════════════════════════════════════════════════════════
  Dựa trên slide: Group frames → Average scores → Sort → TopK

  1. CLIP Score trung bình
     - Tính query-to-frame similarity cho từng frame trong shot
     - avg_clip = mean(clip_scores)

  2. Temporal Consistency
     - Khoảng cách thời gian giữa các frame
     - consistency = 1 / (1 + max_gap)

  3. Composite Score
     validation_score = 0.7 * avg_clip + 0.3 * temporal_consistency

IV. GIAI ĐOẠN 3: VLM AGENT (src/agent/)
───────────────────────────────────────────────────────────────────────────────

  ══════════════════════════════════════════════════════════════════
  HỖ TRỢ 2 BACKEND: Gemini API (cloud) hoặc Ollama (local)
  ══════════════════════════════════════════════════════════════════
  Auto-detect: nếu Ollama server đang chạy → dùng local model,
  nếu không → fallback về Gemini API (nếu có GEMINI_API_KEY).

  ══════════════════════════════════════════════════════════════════
  THÀNH PHẦN:
  ══════════════════════════════════════════════════════════════════

  1. Brain (brain.py / local.py)
     - Gemini: VlmBrain, model=gemini-2.5-flash-lite (text-only)
     - Local: LocalBrain, model=llava:7b (qua Ollama)
     - parse_react_response(): {thought, action, action_input, answer, finished}
     - Tự động load GEMINI_API_KEY từ .env nếu chưa set

  2. Tools (tools.py / local.py)
     - Gemini: CaptionTool + OCRTool (gemini-2.5-flash-lite, hỗ trợ ảnh)
     - Local:  LocalCaptionTool + LocalOCRTool (moondream qua Ollama, ưu tiên)
     - DetectTool: object detection YOLOv8 (placeholder, chưa cài)
     - ASRTool: speech-to-text Whisper (placeholder, chưa cài)

  3. Agent (react.py)
     - Vòng lặp ReAct (tối đa 5 bước):
       Thought → Action → Tool → Observation → (Answer / Repeat)
     - Auto-detect Ollama khi khởi tạo (create_agent)

VIII. LƯU Ý QUAN TRỌNG
───────────────────────────────────────────────────────────────────────────────

  1.  GEMINI_API_KEY: Có thể set bằng:
        - set GEMINI_API_KEY=AIza... (cmd, tồn tại trong session)
        - Hoặc ghi vào file .env (tự động load, khỏi set lại)

  2.  Ollama (local model):
        - Cài: https://ollama.com/download
        - Pull model:
            ollama pull moondream     # RTX 3050 4GB (1.8B, ~1GB)
            ollama pull llava         # GPU >8GB (7B, ~4.7GB)
        - Chạy server: ollama serve (tự động nếu cài bản desktop)
        - Code tự động detect, ưu tiên moondream > llava
        - Nếu không có Ollama → fallback về Gemini API

  3.  GPU vs CPU:
        - CLIP embedding → GPU (sau khi cài torch CUDA)
        - FAISS index → CPU (faiss-cpu, Windows không có bản GPU)
        - Agent (Ollama + moondream) → GPU (RTX 3050 4GB, ~3-8s/lần)
        - Agent (Gemini) → gọi API Google (cần Internet)

  4.  Temporal Search:
        - So sánh FRAME VỚI FRAME (không phải query với frame)
        - tolerance_threshold: 3 (mặc định). Tăng → segment dài hơn

  5.  YOLOv8 + Whisper: Chưa cài. DetectTool và ASRTool trả placeholder.
        - uv add ultralytics để dùng YOLOv8
        - uv add openai-whisper để dùng Whisper

  6.  Chạy UI:
        uv run python -m src.cli.main serve-ui --experiment-name "20260616_..."

  7.  Chạy test:
        uv run pytest  (48 tests)

  8.  File .env:
        GEMINI_API_KEY=AIzaSy...
        (Tự động load bởi VlmBrain, CaptionTool, OCRTool)

  9.  CLIP tokenizer có giới hạn 77 tokens. Nếu query dài hơn,
      tự động truncate (truncation=True trong clip_model.py).
